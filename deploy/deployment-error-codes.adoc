= 疑難排解 ONTAP 工具部署錯誤
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
如果遇到部署問題，請審查日誌和錯誤代碼以診斷和解決問題。從 ONTAP tools for VMware vSphere 10.6 開始，從 Pod 收集的日誌包含 MongoDB、RabbitMQ 和 Vault 的日誌，以及所有 Pod 的狀態和描述。ONTAP tools 10.6 也新增了稽核記錄，以提高疑難排解期間的可追溯性。這些是對現有 ONTAP tools 服務日誌的補充，進一步增強了支援性和疑難排解。



[[collect-the-log-files]]
== 收集記錄檔

您可以透過 ONTAP tools Manager 使用者介面中的選項收集 ONTAP tools for VMware vSphere 的日誌檔案。技術支援人員可能會要求您收集這些日誌檔案，以協助疑難排解問題。


NOTE: 從 ONTAP tools Manager 產生記錄包含所有 vCenter Server 執行個體的所有記錄。從 vCenter 用戶端使用者介面產生記錄的範圍僅限於所選的 vCenter Server。

.步驟
. 從網路瀏覽器啟動 ONTAP 工具管理員： `\https://<ONTAPtoolsIP>:8443/virtualization/ui/`
. 使用您在部署期間提供的 VMware vSphere 管理員認證 ONTAP 工具登入。
. 從側欄中選擇 * 日誌套件 * 。
+
此作業可能需要數分鐘的時間。

. 選取 * 產生 * 以產生記錄檔。
. 輸入日誌套件組合的標籤、然後選取 * 產生 * 。
+
下載 tar.gz 檔案並傳送給技術支援人員。



請遵循下列步驟，使用 vCenter 用戶端使用者介面產生記錄套件：

.步驟
. 登入 vSphere 用戶端。
. 從 vSphere Client 首頁、前往 * 支援 * > * 記錄套件 * > * 產生 * 。
. 提供日誌包標籤並產生日誌包。文件生成後，您可以看到下載選項。下載可能需要一些時間。



NOTE: 產生的記錄套件會取代過去 3 天或 72 小時內產生的記錄套件。



[[deployment-error-codes]]
== 部署錯誤代碼

您可能會在部署 VMware vSphere 、重新開機和還原作業的 ONTAP 工具期間遇到錯誤代碼。
錯誤代碼長度為五位數、前兩位數代表發生問題的指令碼、後三位數代表該指令碼內的特定工作流程。

所有錯誤日誌都記錄在 /var/log/otvng 目錄下的 ansible-perl-errors.log 日誌檔中，以便於追蹤和解決問題。此日誌檔包含錯誤代碼和失敗的 Ansible 工作。


NOTE: 本頁提供的錯誤代碼僅供參考。如果錯誤仍然存在或未提及解決方案，請聯絡支援團隊。

下表列出錯誤代碼和對應的檔案名稱。
