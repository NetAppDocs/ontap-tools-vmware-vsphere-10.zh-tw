[[deployment-and-high-availability]]
== 部署和高可用度

.ONTAP tools 支援哪些 VMware vSphere、ESXi 和 ONTAP 版本？
支援的 ONTAP 、 ESXi 和 vCenter Server 版本因 ONTAP 工具版本而異。用於部署 ONTAP 工具虛擬機器的 ESXi 主機和 vCenter Server 也可能具有與 ONTAP 工具部署後可管理的版本分隔且更嚴格的需求。支援的版本會隨版本而異，因此請務必查看您正在執行之版本的 https://mysupport.netapp.com/matrix["NetApp 互通性對照表工具"^]和 link:deploy/prerequisites.html["適用於 VMware vSphere 的 ONTAP 工具的要求和設定限制"]。

.我該使用哪個版本的 ONTAP tools，9.x 還是 10.x？
大多數環境都能從移轉到最新的 ONTAP tools 10.x 版本中獲得優點。與 ONTAP tools 9.13 相比，它增加了對 VMFS 的 NVMe-oF 支援，符合較新的 ONTAP 和 VMware vSphere 版本資格，並且每個應用裝置支援多個 vCenter Server 執行個體，而不僅僅是一個。只有當您的環境有最新的 10.x 版本尚不支援的特定相依性時，繼續使用 ONTAP tools 9.x 才有意義，而且由於 ONTAP tools 9.x 即將終止支援，因此值得規劃儘早移轉。請查看 https://mysupport.netapp.com/site/info/version-support["NetApp 支援網站 - 軟體版本支援"^]頁面以了解目前的終止支援日期。請參閱 link:release-notes/ontap-tools-9-ontap-tools-10-feature-comparison.html["ONTAP tools for VMware vSphere 各版本功能比較"] 和 https://mysupport.netapp.com/matrix["NetApp 互通性對照表工具"^]以確認哪個版本符合您的 ONTAP、ESXi 和 vSphere 版本。

.隨著需求的成長，我該如何擴充我的 ONTAP tools 部署？
ONTAP tools 始終以超小型（XS）單一節點應用裝置的形式初步部署，為 NFS 和 VMFS 資料儲存區提供核心服務。如果您之後需要更多資源、更高的彈性，或是 vVols 和 HA，您可以垂直擴充到小型、中型或大型，或擴充到 HA；HA 部署是多節點的，使用三個節點，並且需要一個內容庫，而大型部署僅支援 HA。若要支援 HA 擴充，請將應用裝置部署在 ESXi 叢集或資源池中，並確保啟用 CPU 熱新增和記憶體容量熱插拔；從 ONTAP tools 10.6 開始，新部署預設啟用這些設定。每種規模的 CPU、記憶體容量和磁碟資源列於 link:deploy/prerequisites.html["適用於 VMware vSphere 的 ONTAP 工具的要求和設定限制"]，因此可以安全地從預設的 XS 規格開始，並根據需求的增長擴充。ONTAP tools 僅支援垂直擴充：您只能增加節點大小，而無法減少節點大小，啟用 HA 後，您無法回復至非 HA 的單一節點組態。有關部署、規模和擴充步驟，請參閱 link:deploy/quick-start.html["VMware vSphere ONTAP 工具快速入門"]、link:deploy/ha-workflow.html["ONTAP 工具的高可用性部署工作流程"] 和 link:manage/edit-appliance-settings.html["垂直擴充 ONTAP tools 並啟用高可用性"]。

.高可用度保護什麼？我應該考慮哪些因素？
HA 解決方案旨在協助從單一節點主機故障、網路故障、客體作業系統故障或 ONTAP tools 應用程式失敗中恢復。HA 部署使用三個節點，這些節點必須位於同一個子網路中，以進行節點間通訊。必須啟用 CPU 熱新增與記憶體容量熱插拔；HA 工作流程還需要適用於 vVols 資料儲存區的 VASA Provider。請參閱 link:deploy/ha-workflow.html["ONTAP 工具的高可用性部署工作流程"] 以了解設定步驟。

.我是否需要高可用度的（HA）部署？何時應該使用？
如果您僅使用不含 vVols 的 NFS 或 VMFS 資料存放區，則不需要 HA，但它仍可提供更廣泛的恢復力，以防範單一節點主機、網路、訪客作業系統或 ONTAP tools 應用程式失敗。必須使用 HA 才能讓 VASA Provider 服務對 vVols 資料存放區持續可用，因此如果您使用 vVols，或者需要比單一節點部署更高的服務恢復力及每個服務更多的容器，請使用 HA 部署。

.單一 ONTAP tools 10.x 部署能否管理多個 vCenter Server 執行個體？
是的。ONTAP tools 9.x 每個應用裝置僅支援一個 vCenter Server，而 ONTAP tools 10.x 則支援多租戶，可讓您從單一 ONTAP tools Manager 介面管理多個 vCenter Server 執行個體，進而減少應用裝置數量及整體資源需求。如果您在多個 vCenter Server 執行個體中使用 vVols 資料存放區，請將自我簽署憑證升級為 CA 簽署憑證，以確保安全的通訊。請參閱 link:configure/add-vcenter.html["將 vCenter Server 執行個體新增至ONTAP工具"] 以瞭解步驟。



[[networking-and-ports]]
== 網路和連接埠

.ONTAP tools 部署需要多少個 IP 位址，每個 IP 位址的用途是什麼？
單一節點部署需要同一子網路上的三個唯一的靜態 IPv4 位址：

* *ONTAP tools IP* （先前為負載平衡器 IP）：ONTAP tools Manager (`https://<ONTAPtoolsIP>:8443/virtualization/ui/`）、REST API、VASA 供應商、Storage Replication Adapter （SRA）與 vSphere Client 外掛的外部端點。
* *ONTAP tools 虛擬 IP*（以前稱為節點互連 IP）：指派給 Kubernetes API 伺服器，並用作 Kubernetes 控制平面的虛擬 IP。
* *節點 IP*：用於診斷 shell 和 SSH 存取的節點管理位址。


高可用度部署會為第二個和第三個節點各增加一個額外的節點 IP 位址；ONTAP tools IP 和虛擬 IP 在所有節點之間共享。請參閱 link:deploy/prerequisites.html["適用於 VMware vSphere 的 ONTAP 工具的要求和設定限制"] 和 link:deploy/pre-deploy-checks.html["ONTAP tools 的部署前要求"] 以取得完整的部署工作表。

.ONTAP tools 使用哪些網路連接埠？
ONTAP tools 將連接埠 443 和 8443 公開為 ONTAP tools Manager、REST API、VASA Provider 以及 vSphere Client 外掛後端的外部直通連接埠。連接埠需求表中的其餘連接埠是應用裝置的 Kubernetes 叢集內部使用的節點間連接埠；在單一節點部署中，它們不需要外部存取，而在 HA 部署中，所有三個節點必須能夠在這些連接埠上互相連線，包括用於 Pod 間通訊的 UDP 8472。如需完整的連接埠表，請參閱 link:deploy/prerequisites.html["適用於 VMware vSphere 的 ONTAP 工具的要求和設定限制"]。



[[certificates-and-security]]
== 憑證與安全性

.ONTAP tools 對 vCenter 伺服器憑證有哪些要求？
憑證只有在能夠證明您所連接伺服器的身份時，才能確保連線安全。主題備用名稱（SAN）擴充功能提供了這種證明：它列出了憑證有效的 DNS 名稱和 IP 位址。

vCenter 伺服器機器的 SSL 憑證必須符合這些要求：

* SAN 包含 vCenter 伺服器的 DNS 名稱和 IP 位址。
* SAN 包含 vCenter 伺服器主網路識別碼（PNID），且 PNID 與 DNS 名稱相符。
* SAN 中的每個名稱都能在 DNS 中解析。


如果憑證沒有 SAN，或 SAN 與 vCenter Server 的 DNS 名稱、IP 位址或 PNID 不符，ONTAP tools 作業將因憑證驗證錯誤而失敗。此驗證無法關閉。在新增 vCenter Server 執行個體之前，請先使用 vSphere Certificate Manager 修正 SAN。如需憑證需求與範例，請參閱 link:configure/add-vcenter.html["將 vCenter Server 執行個體新增至ONTAP工具"]。

.為什麼新增儲存設備後端時憑證驗證失敗？如何解決這個問題？
ONTAP tools 預設會驗證儲存設備後端憑證，原因與驗證 vCenter 伺服器憑證相同：SAN 擴充證明了該憑證所屬的叢集或 SVM 管理 LIF。預設的 ONTAP 自簽憑證通常沒有 SAN，因此在新增儲存設備後端時會驗證失敗。

要解決驗證失敗的問題：

* 將憑證取代為 SAN 包含叢集或 SVM 管理 LIF 的 IP 位址或 DNS 名稱的憑證，然後在新增或重新新增儲存設備後端時取得並授權更新後的憑證。
* 如果無法立即更換憑證，請從維護主控台停用憑證驗證。這會略過所有已設定儲存設備後端的驗證，且不適用於 vCenter Server 憑證。


如果儲存設備後端憑證在您續約之前過期， ONTAP tools 會將儲存設備後端標記為未知，因為它無法再連線至儲存系統。請參閱 link:configure/add-storage-backend.html["為 ONTAP tools 新增儲存後端"] 和 link:manage/change-valid-flag.html["更改證書驗證標誌"] 以取得步驟。



[[datastores-and-storage-backends]]
== 資料存放區與儲存設備後端

.我可以管理哪些資料儲存類型和協定？
ONTAP tools 支援這些資料存放區類型和協定：

* *NFS*：NFSv3 和 NFSv4.1。
* *VMFS*：iSCSI、FC、NVMe/TCP 和 NVMe/FC。
* *vVols*：透過 VASA 供應商配置與代管。


請參閱 link:configure/create-datastore.html["在 ONTAP 工具中建立資料存放區"] 以了解建立步驟。

.為什麼 ONTAP tools 會建立這麼多 igroup，我可以使用現有的扁平化 igroup 嗎？
ONTAP tools 依設計採用巢狀 igroup 模型：

* 父 igroup 代表每個資料存放區的存取，而子 igroup 代表每個 ESXi 主機。LUN 對應套用於子 igroup。
* 這種結構允許 ONTAP tools 在多個資料存放區中重複使用主機的子 igroup，而不是為每個資料存放區重複主機存取，並且它為 ONTAP tools 提供了裝載、取下和主機更新作業所需的精細、個別主機控制。
* ONTAP tools 代管的 igroup 使用  `otv_` 前置字元。


如果您已經有對應至 ONTAP tools 所探索之資料儲存的扁平 igroup，ONTAP tools 會在探索期間將其轉換：它會將原始 igroup 保留為子 igroup，並加上 `otv_` 前置詞重新命名，同時在其上方建立一個父 igroup，而不會變更底層的啟動器對應。未對應至資料儲存的 igroup（例如開機 LUN igroup）則保持不變。

由於 ONTAP tools 依賴這種父子結構來追蹤主機存取，因此請勿手動重新命名、編輯或刪除 ONTAP tools 代管的 igroup。請改用 ONTAP tools 裝載、取下和主機更新工作流程。詳情請參閱 link:manage/nested-igroups.html["ONTAP tools 中的巢狀 igroup 管理"] 和 link:manage/igroup-workflow.html["ONTAP tools 如何管理 igroup 和匯出原則"]。

.全域儲存設備後端和本機儲存設備後端有什麼區別？
儲存後端在範圍和憑證方面各不相同：

* *Global storage backend*：僅使用 ONTAP 叢集認證在 ONTAP tools Manager 中新增一次。在與 vCenter Server 建立關聯之前，它不會連結至任何 vCenter Server，並提供 vVols 管理所需的叢集層級探索。
* *本機儲存設備後端*：使用叢集或 SVM 憑證為每個 vCenter Server 新增，且僅供該 vCenter Server 使用。僅 SVM 憑證即足以滿足 VMFS 資料存放區與儲存複寫介面卡（SRA）工作流程的需求，但不適用於 vVols。


請參閱 link:configure/add-storage-backend.html["為 ONTAP tools 新增儲存後端"] 和 link:configure/associate-storage-backend.html["在 ONTAP 工具中將儲存後端與 vCenter Server 執行個體建立關聯"] 以取得步驟。

.搭配 ONTAP 工具使用 vVols 需要什麼？
vVols 資料儲存區工作流程依賴已啟用並向所選 vCenter Server 註冊的 VASA Provider 服務。ONTAP tools 使用 VASA Provider 來建立與維護 vVols 資料儲存區表示法，而虛擬機器儲存原則會使用來自 NetApp vVols 儲存設備類型供應商的規則。在 HA 設定中，HA 工作流程也需要 VASA Provider 以用於 vVols 資料儲存區。請參閱 link:manage/enable-services.html["在 ONTAP tools Manager 中啟用選用服務"] 和 link:configure/registration-process.html["在 ONTAP 工具中將 VASA Provider 註冊到 vCenter Server 執行個體"] 以了解設定步驟。

.VMware 已棄用 vVols。這對 ONTAP tools 使用者意味著什麼？
Broadcom 已從 VMware Cloud Foundation 和 VMware vSphere Foundation 9.0 開始淘汰 vVols，並計劃在未來版本中停止此功能。對於新部署，請規劃使用 VMFS 或 NFS 資料存放區，並保持停用 VASA Provider，除非您目前正在使用 vVols。請查看 ONTAP tools 版本說明，以了解各版本中的 vVols 支援狀況。



[[protection-and-disaster-recovery]]
== 保護與災難恢復

.如何使用 ONTAP tools for VMware vSphere 保護資料存放區？
您可以將使用 iSCSI 或 FC 協定且符合條件的 VMFS 資料儲存新增至具有 SnapMirror 關係的保護群組中，並使用 Asynchronous 或 AutomatedFailOverDuplex 原則來保護它。當主機叢集包含來自多個 SVM 的資料儲存時，請改用精細的資料儲存保護工作流程，在保護群組層級選擇並保護資料儲存。請參閱 link:manage/protect-ds.html["在 ONTAP tools 中保護 VMFS 資料存放區"] 和 link:protect/protect-multiple-ds.html["使用 ONTAP tools 保護叢集中的資料存放區"] 以了解步驟。

.如何使用 ONTAP 工具進行災難恢復？
對於基於陣列的災難恢復，請在 ONTAP tools 中啟用 SRA 服務，並在 VMware Live Site Recovery 應用裝置上安裝 SRA 介面卡。在執行 SRA 工作流程之前，請在來源和目的地叢集上使用相同的自訂 SnapMirror 排程。在新的 SRA 設定中，務必執行測試容錯移轉；若跳過此步驟，可能會導致重新保護作業失敗。如需設定步驟，請參閱 link:protect/enable-storage-replication-adapter.html["在 ONTAP 工具中設定 SRA 以保護資料儲存區"]。

.我可以使用 SRA 和 VMware Live Site Recovery 保護哪些資料儲存類型？
SRA 支援 iSCSI 和 FC 上的 NFSv3 資料儲存和 VMFS 資料儲存。NVMe-oF 資料儲存不支援災難恢復，且 VMware Live Site Recovery 不支援 NFSv4.1 或 FlexGroup 資料儲存的陣列型複寫。一致性群組僅支援 iSCSI 和 FC；將 NFS 磁碟區加入一致性群組會導致裝置探索失敗。

.SnapMirror 作用中同步保護與基於 SRA 的災難恢復有何不同？
主機叢集保護工作流程針對 VMFS 資料存放區使用 SnapMirror 作用中同步。ONTAP tools 10.6 也支援精細的資料存放區保護，讓您可以使用 iSCSI 或 FC 選擇符合條件的 VMFS 資料存放區，並在保護群組層級套用保護。SRA 則與 VMware Live Site Recovery 整合，以進行陣列型災難恢復工作流程。如需資格詳細資料，請參閱 link:protect/granular-datastore-protection-concept.html["ONTAP tools 中精細資料存放區保護資格標準"]。



[[access-control-backup-and-support]]
== 存取控制、備份和支援

.存取控制在 ONTAP tools、vCenter 和 ONTAP 之間是如何運作的？
存取在兩個環境中受到控制：vCenter 伺服器權限治理對 vSphere 物件的存取，而 ONTAP 角色治理儲存設備操作。ONTAP tools 會先檢查 vCenter 角色，然後檢查與儲存設備後端關聯的 ONTAP 角色。ONTAP tools 不會在 vCenter 或 ONTAP 中建立使用者帳戶，因此系統管理員需建立所需的服務帳戶。如需詳細資訊，請參閱 link:concepts/rbac-learn-about.html["了解 ONTAP tools 中的 RBAC"]。

.如何在 ONTAP tools for VMware vSphere 中設定角色型存取控制（RBAC）？
由於 ONTAP tools 不會在 vCenter 或 ONTAP 中建立使用者帳戶，因此 vSphere 系統管理員必須在兩個環境中建立所需的服務帳戶並指派角色。在 vCenter Server 中，ONTAP tools 透過遠端外掛公開的其他物件來擴充 RBAC 模型。在 ONTAP 中，存取是透過指派給您在驗證儲存設備後端時所提供之使用者的 ONTAP 角色來控制；ONTAP tools 提供預先定義的角色和 JSON 角色檔案，您可以使用這些檔案來指派儲存設備後端作業所需的最低權限。如需設定步驟，請參閱 link:concepts/rbac-vcenter-use.html["vCenter 伺服器 RBAC 如何與 ONTAP tools for VMware vSphere 搭配運作"] 和 link:configure/configure-user-role-and-privileges.html["為 ONTAP tools 配置 ONTAP 使用者角色和權限"]。

.ONTAP tools 多久備份一次應用裝置？備份的用途是什麼？
從 ONTAP tools 10.5 開始，備份預設為啟用，並每 10 分鐘執行一次。備份檔案儲存在資料存放區中，可讓您在原始虛擬機器遺失時重新部署及恢復 ONTAP tools 應用裝置本身；它們不是 ONTAP tools 所管理之 ONTAP 叢集或 vCenter Server 組態的備份。您可以將頻率變更為 10 到 60 分鐘之間。請參閱 link:manage/backup-settings.html["編輯 ONTAP tools 備份設定"] 和 link:manage/recover-backup.html["從備份中恢復 ONTAP tools for VMware vSphere"] 以了解步驟。

.我可以停用 ONTAP tools 備份嗎？
您可以停用備份，但請勿停用，因為這會阻止 ONTAP tools 維持較低的恢復點目標。停用備份不會刪除現有的備份檔案。請參閱 link:manage/backup-settings.html["編輯 ONTAP tools 備份設定"] 以了解相關步驟。

.當需要進行疑難排解或聯絡支援時，我可以在哪裡找到日誌？
您可以在 ONTAP tools Manager 或從 vSphere Client 產生日誌套裝組合。在 ONTAP tools Manager 中產生的套裝組合包含所有代管 vCenter Server 執行個體的日誌；在 vSphere Client 中產生的套裝組合範圍則僅限於所選的 vCenter Server。下載產生的歸檔，並在要求時提供給技術支援。請參閱 link:deploy/deployment-error-codes.html["ONTAP tools 部署錯誤程式碼"] 以了解步驟。

.如何收集用於 ONTAP tools 疑難排解的診斷資訊？
除了日誌套裝組合之外，您還可以從維護主控台啟用對  `diag` 使用者帳戶的遠端診斷（SSH）存取。一次只允許一個 diag 登入工作階段，且存取會在隔天午夜或您再次以 diag 使用者身分登入時自動停用。使用此存取可進行比日誌套裝組合所提供更深入的疑難排解，並請先產生日誌套裝組合，以便技術支援擁有基準日誌可供使用。如需相關步驟，請參閱 link:manage/configure-remote-diagnostic-access.html["配置 ONTAP 工具的遠端診斷存取權限"]。



[[upgrade-migration-and-automation]]
== 升級、移轉和自動化

.我可以直接升級到最新的 ONTAP tools 10.x 版本嗎？
支援從最新版本的前兩個版本（N-2）直接升級。如果您目前版本較舊，請先升級到支援直接升級到最新版本的最早版本，然後再升級到最新版本。請啟用低 RPO 備份並在開始前下載備份，因為失敗的升級不一定能回復，此時恢復將依賴低 RPO 備份或快照恢復。請參閱 link:upgrade/upgrade-ontap-tools.html["將 ONTAP tools for VMware vSphere 10.x 升級至 10.6"] 以了解支援的升級路徑與步驟。

.如何從 ONTAP tools 9.x 移轉至最新的 10.x 版本？
僅支援從特定 ONTAP tools 9.x 版本進行移轉。移轉路徑取決於您的環境是否使用 vVols：使用 vVols 的環境會移轉 VASA Provider 並更新 SRA，而僅使用 NFS 和 VMFS 資料儲存的環境則移除 9.x 部署並部署 10.x。使用 NVMe/FC 的 vVols 資料儲存在移轉後將無法運作，因為 ONTAP tools 10.x 僅支援搭配 VMFS 資料儲存的 NVMe-oF。如需支援的來源版本和步驟，請參閱 link:migrate/migrate-to-latest-ontaptools.html["將 ONTAP tools for VMware vSphere 9.xx 移轉至 10.6"]。

.我可以使用 REST API 自動化 ONTAP tools 作業嗎？
是的。ONTAP tools 提供用於自動化的 REST API，與 ONTAP 叢集 REST API 分隔。API 存取使用 ONTAP tools IP 位址和連接埠 8443；使用 ONTAP tools Manager 認證進行驗證以取得存取權杖，然後在 `x-auth`標頭中傳送權杖。長時間執行的作業可以非同步執行，並傳回要監控的作業。請參閱 link:automation/learn-rest-api.html["了解 ONTAP tools REST API"] 和 link:automation/first-call.html["進行第一次 ONTAP tools REST API 呼叫"] 以開始使用。
